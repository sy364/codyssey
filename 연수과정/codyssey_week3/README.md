# Mini NPU Simulator

## 1. 실행 방법

Python 3.8 이상 환경에서 실행합니다.

``` bash
python3 main.py
```

실행 후 모드를 선택합니다.

-   `1`: 사용자 입력 모드 (3×3)
-   `2`: `data.json` 분석 모드

`data.json`은 `main.py`와 같은 디렉터리에 위치시킵니다.

## 2. 구현 요약

### MAC 연산

`calculate_mac()` 함수에서 패턴과 필터의 같은 위치의 값을 곱한 뒤 모두
더합니다.

``` text
pattern[i][j] × filter[i][j]
                ↓
            누적 합산
                ↓
              score
```

두 개의 필터(Cross, X)에 각각 MAC 연산을 수행하고 점수를 비교하여 더
높은 점수의 필터를 선택합니다.

### 라벨 정규화

`normalize_label()` 함수를 별도로 두어 입력 데이터의 라벨 표현을
프로그램 내부의 표준 라벨로 통일했습니다.

-   `+` → `Cross`
-   `cross` → `Cross`
-   `x` → `X`

JSON의 표현 방식이 달라도 프로그램의 판정 및 PASS/FAIL 비교에서는 항상
표준 라벨을 사용합니다.

### 동점 처리

두 점수의 차이가 `1e-9`보다 작으면 부동소수점 오차를 고려하여 동점으로
처리합니다.

``` python
abs(score_cross - score_x) < 1e-9
```

동점인 경우 판정은 `UNDECIDED`가 되며, `expected`와 다르면 FAIL로
처리합니다.

### 데이터 크기 처리

패턴 키가 `size_5_1`, `size_13_2`와 같은 형태이므로 키를 `_`로 분리하여
크기 N을 추출합니다.

추출한 N을 이용해 `filters`의 `size_N` 필터를 선택합니다.

``` text
size_13_2
   ↓
N = 13
   ↓
size_13
   ↓
Cross / X 필터 선택
```

### 성능 측정

`measure_performance()`에서 MAC 연산 함수 호출 구간만 `time`으로
측정합니다.

각 크기의 연산을 10회 반복하고 평균 시간을 ms 단위로 계산합니다. 입력,
출력, JSON 파일 읽기 시간은 측정 대상에서 제외합니다.

## 3. 결과 리포트

### 실패 원인 분석

현재 `data.json` 분석 결과 일부 케이스에서 FAIL이 발생했습니다.

`size_5_1`, `size_13_2`, `size_25_1`은 Cross와 X의 MAC 점수가 허용오차
범위 안에서 동일하게 계산되었습니다.

이 경우 단순히 부동소수점 값의 작은 차이를 이용하여 하나의 라벨을
선택하면 판정 결과가 불안정해질 수 있습니다.

따라서 `abs(score_cross - score_x) < 1e-9` 조건을 사용하여 두 점수를
동점으로 판단하도록 했습니다.

동점인 경우 `UNDECIDED`를 반환하도록 구현했습니다.

해당 케이스의 `expected` 값은 각각 `X`, `Cross`, `X`이므로 `UNDECIDED`와
일치하지 않아 FAIL이 됩니다.

이는 MAC 연산 로직의 오류라기보다 요구사항에서 정의한 동점 처리 정책과
데이터의 expected 값이 일치하지 않아서 발생한 결과입니다.

또한 JSON의 `+`, `cross`, `x`처럼 서로 다른 라벨 표현을 그대로 비교하지
않고 `normalize_label()`을 통해 `Cross`, `X`로 통일했습니다.

이렇게 하면 데이터의 라벨 표기 방식 때문에 발생하는 불필요한 FAIL을
방지할 수 있습니다.

필터와 패턴의 크기가 서로 다른 경우에는 MAC 연산을 수행하지 않고 해당
케이스를 FAIL 처리하도록 구성했습니다.

이를 통해 데이터 오류와 프로그램 로직 오류를 구분할 수 있도록 했습니다.

### 시간 복잡도 분석

N×N 크기의 패턴과 필터를 MAC 연산할 때 바깥 반복문과 안쪽 반복문이 각각
N번 실행됩니다.

따라서 전체 위치의 개수는 `N × N = N²`입니다.

각 위치에서는 곱셈 한 번과 누적 덧셈 한 번을 수행하므로 위치 하나의
연산은 일정한 시간에 처리됩니다.

따라서 전체 MAC 연산의 시간 복잡도는 `O(N²)`입니다.

예를 들어 3×3은 9번, 5×5는 25번, 13×13은 169번, 25×25는 625번의 위치
연산을 수행합니다.

N이 커질수록 처리해야 하는 데이터 위치가 제곱 형태로 증가합니다.

실제 측정 시간 역시 일반적으로 연산 횟수가 증가하면서 함께 증가하는
경향을 확인할 수 있습니다.

다만 작은 입력에서는 운영체제 스케줄링이나 Python 함수 호출 등의
영향으로 측정값이 완전히 비례하지 않을 수 있습니다.

성능 측정에서는 각 크기를 10회 반복하고 평균을 사용하여 이러한 측정
오차의 영향을 줄였습니다.

이러한 결과를 통해 패턴 크기가 증가하면 MAC 연산량이 N²에 비례하여
증가한다는 것을 확인할 수 있습니다.

## 4. 새로운 라벨 추가 시 확장 방법

예를 들어 `data.json`에 새로운 라벨 `0`이 추가된다고 가정합니다.

확장 순서는 다음과 같습니다.

1.  먼저 `normalize_label()`에 `0`이 어떤 표준 라벨을 의미하는지
    정의합니다.
2.  입력 라벨 `0`을 프로그램 내부의 새로운 표준 라벨로 변환하도록 정규화
    로직을 수정합니다.
3.  그 다음 판정 로직에서 새로운 라벨을 선택할 수 있는 조건과 비교
    기준을 추가합니다.
4.  콘솔 출력에서도 새로운 표준 라벨이 일관되게 표시되는지 확인합니다.
5.  마지막으로 `data.json`에 새로운 라벨을 사용하는 테스트 케이스를
    추가합니다.
6.  기존 `Cross`, `X` 케이스가 영향을 받지 않는지도 함께 테스트합니다.
7.  PASS/FAIL 결과와 실패 원인을 확인하여 기존 기능의 회귀 여부를
    검증합니다.

즉, **정규화 → 판정 → 출력 → 테스트** 순서로 확장하고, 마지막에 기존
기능의 회귀 테스트까지 수행합니다.

새로운 라벨이 단순한 표기 변경인지, 실제로 새로운 필터/판정 대상이
추가되는 것인지에 따라 판정 로직과 데이터 구조도 함께 확장해야 합니다.
